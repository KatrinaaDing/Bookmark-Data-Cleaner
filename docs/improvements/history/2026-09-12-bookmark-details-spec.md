# Bookmark details and cleanup design

> Historical record. Describes the original scope and evidence, not current implementation instructions. Use the [improvement index](../README.md) and [active plan](../plans/2026-09-19-public-release-plan.md) for current priorities. Original task checkboxes are not a current completion tracker.

Approved in the conversation on 12 September 2026. This implements the existing extension's detail and cleanup flows.

- Keep the local, dependency-free TypeScript extension, existing name/icon and blue/white styling. Keep the unchecked-checkbox appearance unchanged.
- Details contains three softly tinted sections: Basic information (bookmark title, website, truthful recency, expandable address), Bookmark (Saved in with folder breadcrumbs, editing/moving, duplicates and explicit additional copies), Website data (truthful detected-cookie availability/count, understandable consequences, affected saved pages/sites, direct Clean up action). Remove technical Storage scope and bulk history Known URLs from the ordinary detail view; retain accurate origin details in cleanup review.
- A bookmark's primary title is its saved title. Distinguish bookmark last opened from website last visited. Missing cookie access is Not checked, not zero. A saved or moved bookmark reports its actual destination and updates the inspected record/list.
- Desktop details remains beside the list in a 3:2 split and sticks within the viewport while the list scrolls. Tall detail content may scroll inside its constrained panel. At 760px or below, use a native modal overlay. Preserve Escape, close, focus return to a refreshed source row, reduced motion, and safe handling of late responses. Resizing with details open must change modes without losing content or trapping focus. Cleanup's native confirmation can open above details.
- Editing an existing bookmark updates that ID, including its folder; creating another copy is explicit. Site details lists existing saved pages with each folder and Edit. A new bookmark requires a visible folder destination. Managed bookmarks/folders are unavailable for mutation.
- Direct single-item cleanup reuses the existing reviewed cleanup engine and does not alter unrelated batch selection. No immediate deletion from a detail/row action.
- Duplicate means the same complete saved URL; do not discard query strings or fragments. Details identifies duplicate copies and their folders. Cleanup review offers unselected duplicate copies with unchecked controls. Adding a copy updates the plan, does not silently add other different pages, and does not duplicate shared site deletion.
- Other pages/sites may share website data. Details presents these separately from duplicate copies. Cleanup review repeats warnings for the selected data categories and lists bookmarks that will remain. Bookmark-only cleanup must not warn that website data will be lost. Include related detected sites where known selected cookie or origin scope overlaps, without claiming that inventory discovers every website.
- Freeze cleanup choices while preparing and use the identical immutable choices snapshot to prepare and build a plan. Offer Back from review to edit choices. A final reviewed confirmation is always required.
- Site inventory groups history by website in one pass and parses each history/bookmark URL once per indexing pass. Preserve parent-domain and partition semantics, known nondefault origins, lookalike isolation, unknown dates. Avoid building a display of every history URL. Basic inventory may be rendered before optional history enrichment; date sorting must not look complete while dates load. Load once per workspace, refresh after mutations and on request; prepare fresh deletion targets at review.
- Update or close details after cleanup so the list, results and counts agree. Permission failures and partial read failures must remain visible; do not silently pretend cleanup is ready when scope preparation failed.
- No checkbox contrast change, age-filter/search feature, backup feature, automatic cleanup, remote previews, new dependencies, or store publishing in this change. The previously audited exact-cookie-removal bug is outside this approved detail-flow change; do not claim it is fixed.
